# Contributing to Sourceblender projects

Thanks for helping. Read the target repository's README and any local
`CONTRIBUTING.md` first; project-specific instructions take precedence over
this default.

1. Search existing issues and pull requests. For a substantial change, open an
   issue to agree on scope before writing a large patch.
2. Work from a branch and keep the change focused. Include tests or a concrete
   verification note for changed behavior. Follow the repository's own test
   and formatting commands.
3. Explain the user-visible change, why it is needed, and any migration or
   compatibility impact in the pull request. Link the issue when there is one.
4. Wait for the repository's checks and review requirements before merging.

Never put credentials, private hostnames, personal data, conversation text,
or captured memory payloads in issues, pull requests, tests, or logs. Use
synthetic examples and redact diagnostic output. Report security issues
privately as described in `SECURITY.md`.

Each repository chooses its own license. Check that project's `LICENSE`
before contributing; this organization default does not grant a license for a
repository that lacks one.
