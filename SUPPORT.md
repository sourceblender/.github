# Support

Start with the affected repository's README, examples, and existing issues.
For a usage question or non-security bug, open an issue in that repository
when issues are enabled. Include the version, environment, expected behavior,
actual behavior, and a minimal synthetic reproducer.

Do not post credentials, private infrastructure details, transcripts, or
captured memory. Follow `SECURITY.md` for vulnerabilities. A repository's own
support instructions take precedence over this default.
